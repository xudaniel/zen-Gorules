# Discount approval demo

[English](README.en.md) · [简体中文](README.md)

A small interactive GoRules decision table with three approval outcomes and nine boundary cases, available in English and Chinese.

## Try it in the browser

1. Download [discount-approval.en.json](../../test-data/discount-approval.en.json) using GitHub’s **Download raw file** button.
2. Open <https://editor.gorules.io/> and use **Open** / import to load the file.
3. Open **Simulator**. In the **Request** editor, enter:

   ```json
   {"discount": 8}
   ```

4. Click **Run**. The result is **Sales manager approval**.
5. Change `8` to `3` or `15`, then run again.

Enter the request in the editable **Request** pane. The **Input / Output** panels display results. `8` means an 8% discount, not `0.08`.

For Chinese results, import [discount-approval.json](../../test-data/discount-approval.json) instead. Both graphs have identical conditions and first-hit behavior.

| First matching condition | English approval result |
|---|---|
| `discount <= 5` | Automatically approved |
| `discount <= 10` | Sales manager approval |
| `discount > 10` | General manager approval |

The first matching row wins. A discount of 3 matches the first two conditions, but only the first result is used. Pass-through preserves the input discount in the output.

The example assumes a numeric discount from 0 to 100; it does not add missing-field, type, or range validation. It calculates an approval outcome without sending approval tasks.

## Run the tests

From the repository root:

```bash
python3 -m venv .temp/discount-approval-venv
source .temp/discount-approval-venv/bin/activate
python -m pip install zen-engine==2.0.2
python -m unittest bindings.python.test_sync.ZenEngine.test_discount_approval_demo -v
```

On Windows, activate with `.temp\discount-approval-venv\Scripts\activate`. No Rust build is needed when using the published engine.

The test runs **nine cases in each language**, checking both `engine.evaluate` and `decision.evaluate` against complete expected outputs. They appear as one unittest method with 18 subtests.

| Discount | Expected English approval |
|---|---|
| 0, 3, 5 | Automatically approved |
| 5.01, 8, 10 | Sales manager approval |
| 10.01, 15, 100 | General manager approval |

The JDM `tests` field stores the cases. The English fixture is generated by [build_english.py](../agent-approval/build_english.py), preserving the Chinese original.
